# CodeForge Engine v1.1.0

CodeForge Engine v1.1.0 is a compatibility-focused evidence and safety release.
It keeps the local, CLI-first workflow and does not promote unverified semantic
analysis or optional external tools to stable guarantees.

## Baseline lifecycle

- Baseline pruning now evaluates current diagnostics and removes only `Resolved`
  entries. `Stale` entries are reported and retained for review.
- `baseline prune` is always a dry run unless `--apply` is supplied, and an apply
  additionally requires `--complete-scan` plus complete all-file scan evidence.
- Ambiguous matches, changed-file scopes, language filters, incomplete submission
  counts and unavailable relevant lint engines block destructive writes.
- Rule staleness now compares an explicit rule-semantics version rather than the
  CodeForge software package version.
- The old lifecycle-only `prune()` path was removed; all pruning is evidence-based.

## Diagnostics and evidence

- Review reports include additive coverage metadata for selection scope,
  requested languages, indexed/selected/submitted files, engine availability,
  external-analysis intent and explicit limitations.
- The desktop review view shows the same coverage information.
- Python `None` comparison fixes now operate on AST operands, avoiding string
  literals and unsafe chained-comparison rewrites.
- Java empty-catch detection uses the catch body AST, detects whitespace-empty
  handlers and avoids documented or nonempty handlers.

## Benchmark evidence

- Timing summaries include P95 in addition to samples, mean, median, variance,
  standard deviation, minimum and maximum.
- Benchmark environment records include CodeForge version, operating system,
  architecture, logical CPUs, Git revision/worktree state and local `rustc` and
  `cargo` versions when available.

## Compatibility

- Baseline schema remains version 1.
- SARIF output remains 2.1.0 and existing import compatibility is unchanged.
- Existing review reports without coverage metadata remain readable through an
  explicit default.
- The baseline command behavior is intentionally safer: destructive pruning now
  requires `--complete-scan --apply`; stale entries are never silently removed.
- Rust 1.90 remains the declared MSRV.

## Boundaries

Default scan/review paths do not run project benchmarks. Benchmarks measure
performance and do not prove correctness or semantic equivalence. External
analyzers remain optional; unavailable analysis is not treated as a clean result.
Context/impact, external SARIF import and CodeQL execution remain Experimental.
