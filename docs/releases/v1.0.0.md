# CodeForge Engine v1.0.0

CodeForge Engine v1.0.0 is the first stable release of the local, CLI-first code
analysis, change review and verification workflow.

## What changed

- The workspace, desktop package, Tauri configuration and lockfile now identify
  the release as 1.0.0.
- The CLI can now preview and apply a uniquely matched fix, list transaction
  history and undo a recorded change. Apply is preview-only by default, requires
  explicit approval for review-required fixes, verifies syntax before writing and
  refuses ambiguous selectors.
- Windows x64 and Linux x64 CLI archives are published alongside the desktop
  packages. Every asset has a normalized filename and is covered by
  `checksums.txt`.
- Release preflight validates tag/version consistency and runs formatting,
  Clippy and the full Rust test suite before building artifacts. CI checks the
  declared Rust 1.90 minimum toolchain.

## What stays stable

Native parsing and review, reviewed baselines, transaction history and rollback,
configurable verification, SARIF export and independent Fleet tasks retain their
existing protocol and configuration boundaries. Baseline schema version 1 is
unchanged, and SARIF output remains a standard 2.1.0 document.

A stable workflow can still carry heuristic findings. Syntax-based suggestions
are review candidates, not semantic proof. `apply` records the verification that
ran and refuses unsafe shortcuts; it does not turn a heuristic finding into a
correctness guarantee.

## Experimental boundaries

On-demand context extraction, heuristic impact/test suggestions, local SARIF path
import and optional CodeQL CLI execution remain Experimental. They are opt-in and
outside the default scan path. Name-based relations are ambiguous by design, and
the CodeQL path requires a separately eligible user-supplied installation. The
repository does not claim that these capabilities provide complete scope/type
resolution or real-world CodeQL certification.

Fleet requires successful checks mandated by policy; a missing required tool is
not a pass. An equivalence command records what that command checked, not a formal
proof. Benchmarks measure execution; they do not replace functional tests.

## Verification

Release artifacts are built from the reviewed tag candidate. The release workflow
runs Rust format, Clippy and tests, validates package metadata, publishes only
normalized asset names, and downloads the published assets again to verify their
SHA-256 checksums. Platform acceptance evidence is recorded separately from the
welcome screenshot.

## Security and limitations

Built-in analysis works locally without an account, telemetry or hosted model.
External commands inherit host permissions and environment; timeout and output
limits are not an OS sandbox. Reports can contain source, paths and tool output.
Review evidence before sharing it.

The CLI is the complete primary entry point. The desktop application exposes the
same core semantics for diagnostic browsing, patch review and evidence inspection.
Optional language tools are not bundled and retain their own licenses.
